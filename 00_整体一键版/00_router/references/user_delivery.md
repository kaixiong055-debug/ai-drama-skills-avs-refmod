# 用户交付边界 · V5.1.5

用户已明确：JSON可以内部执行，不得交付给用户；不交付重复的FULL和一键提示词。

工程目录与用户资料目录必须分离。内部保留Canonical JSON、FULL/Runtime中间视图、hash、版本、校验报告、生成记录、装配清单、代码和原始Skills。用户ZIP不得包含这些内部文件，不得把它们放在ZIP里的“内部工程”文件夹继续交给用户。

默认用户资料只包含六份文件：使用说明；中文素材提示词；英文素材提示词；一份中文分镜执行表；一份中文H3一键提示词；一份英文H3一键提示词。存在真实图片时额外提供assets/。不额外交付重复拍摄剧本、文本分镜、原文台账、英文分镜表、Runtime、FULL别名、回归报告或Python脚本。用户明确要求某项时再单独导出。

H3两种语言对应同一剧本。每种语言只保留一个最终文件，内容必须仍是FULL14栏；去掉重复文件，不得删减提示词内容或切换为Runtime。

英文版最终H3文件必须使用“中文段头与导入元数据＋英文FULL14栏正文＋原中文对白”。逐段沿用中文版从段头到subject_definitions之前的全部内容，包括空间预热/视频片段、集数、场景、段类型、成片、最终成片、连续性、续写来源、继承尾音、生成模式、Picture绑定和Speaker绑定等字段及其中文说明值；文件开头的制作状态说明也保留中文。Scene、Hidden LOCK、H3模式REF2VA等固定标识、ID、路径，以及subject_definitions等14栏字段名保持原样，不能自行汉化。subject_definitions开始的英文正文直接沿用内部英文FULL，原中文对白不能翻译或改写。所有正式片段与隐藏LOCK均适用，不得只改首段。内部英文中间视图可保留英文元数据供校验，但不能直接作为用户英文交付文件。转换后只交付唯一英文文件，不另外添加AVS兼容副本。

工具入口：CLI export/source和GUI使用engine.delivery.export_user_project，内部工程默认保存在输出目录旁.ai_drama_internal/<项目目录名>/production。正常用户仅链接或打包用户资料目录。validate/jobs等命令可通过用户资料目录自动定位内部工程。engine.pipeline.export_project仍是供内部调用的底层编译器，其返回目录不是最终用户附件。

已有工程使用：python one_click.py delivery --project <内部工程> --output <用户目录>。待出图审阅稿必须显式加--draft并保留待出图标识；不能把缺图稿改名为READY。生成后检查用户目录没有JSON/源码/内部日志，中文和英文各恰好一份H3提示词，且与内部FULL正文相同。

这份规则只调整交付范围；源Beat保护、状态一致性、图片检查、FULL14栏、真实视频QC等原有要求继续生效。若旧文档中“一次输出全部文件”“随包报告”与此冲突，解释为内部工程输出，不能覆盖此用户交付边界。

## 实际对白语言

提示词正文语言与人物实际说话语言分开。中文小说默认使用普通话：原中文台词逐字保留在对白标签内，禁止翻译、改写或改成英文配音；对白时长、说话人及次数保持原计划，口型对应中文发音。每个含中文对白的正式段落在dialogue_and_audio中写明普通话要求，禁止朗读人物名、时间码、语言标签、英文画面/动作指令，禁止新增旁白。无对白段和隐藏空间预热不新增说话。用户明确要求的其他语言按对应spoken_language处理，不能因英文导出自动切换说话语言。

engine.speech.enforce_spoken_language用于FULL、内部Runtime以及旧工程交付时的规则补齐；重复导出不重复添加约束。它仅添加指令，不重复台词、不修改原对白。交付检查应验证中英文台词逐字一致、无对白片段未变、中文段头未变及素材绑定完整。文本约束通过不代表生成语音已经实测。

人物表演：依据05_storyboard的shots.performance.cn/en，在原镜头时长内补充眼神、眉眼唇颌、自然眨眼与安静呼吸；不机械重复、不新增音效或对白、不改变脸和走位。无脸/道具镜头使用face_visible=false。具体编写要求见05_storyboard/SKILL.md的“镜头内人物表演”。


用户明确要求RefMod时，实际生成的.safetensors可放同一交付目录的RefMod/；宿主工作流JSON仅安装到ComfyUI工作流目录，不散放用户资料中。通用delivery白名单仍保持原规则，RefMod由完成实际编码的代理单独核对并复制。
